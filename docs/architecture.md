# 技术架构与关键决策（FeasAI）

> 面向读者：作者本人（代码基础一般，目标是"看得懂、面试讲得出"）。因此本文件刻意用中文 + 图示，不堆术语。
> 原则：**技术选型保守**（少依赖、易部署、好解释），**代码边界清晰**（纯计算与 LLM 分离）。

## 2. 模块与职责（对应目录）

| 目录 | 职责 | 是否依赖 LLM | 面试讲法（一句话） |
|---|---|---|---|
| `engine/` | 财务模型：现金流表、NPV/IRR/回收期/盈亏平衡/敏感性/情景 | 否 | "把技术经济学的公式写成了可测试的纯函数，保证真算" |
| `knowledge/` | 文档解析(markitdown)、按标题切块、向量化、自研 numpy 余弦检索、引用格式 | 仅 embedding | "借鉴 RAG 思路做资料问答，每个论断可溯源" |
| `llm/` | 各家国内模型统一封装（OpenAI 兼容协议）、prompt 模板 | 是 | "模型可替换，换 Key 就能换厂商" |
| `workflow/` | 假设审核、章节编排、数字注入与校验 | 是 | "像流水线：先审假设、再测算、后写报告，数字不进 LLM 自由发挥" |

## 3. 关键技术决策（为什么这么选）

1. **财务引擎 = 纯 Python 函数 + JSON 输出**
   —— 这是全项目的信任基石。LLM 永远不直接产生财务数字；报告生成时从引擎 JSON 取数注入。测试覆盖公式正确性（对比手算例题）。
2. **界面用 Streamlit 而非自研前端（MVP）**
   —— 作者不写代码，Streamlit 把"表单+图表+文本"全部托管，风险最低；P1 若想更像产品可换 Next.js（参考 NextChat 交互），届时只换壳不换核心。
3. **向量检索自研（numpy 余弦 top-k，不引外部向量库）**
   —— 知识库规模（几百个块）下矩阵乘法检索 <10ms；零部署、纯 Python 可跑
   （符合作者"本机只跑 Python"的约束），且 100 行代码作者看得懂、面试讲得清；
   P2 需要大规模/持久化时再平滑换 chroma/FAISS（add/search 接口不变）。
4. **文档解析用 markitdown（MIT）**
   —— 微软开源，Office/PDF 全格式覆盖，省掉自研解析的大量坑。
5. **大模型统一走 OpenAI 兼容协议**（DeepSeek 等国内厂商均支持）
   —— `.env` 配 `LLM_BASE_URL / LLM_API_KEY / LLM_MODEL / EMBED_BASE_URL / EMBED_API_KEY / EMBED_MODEL` 即可切换厂商。
6. **编排不用重型 Agent 框架（MVP）**
   —— LangGraph/OpenAI Agents SDK 先只做"思想参考"，用 Python 原生顺序流水线实现（少一层抽象，作者更好懂）；M3 后视简历需要再引入 LangGraph 展示多 Agent 能力。
7. **借鉴 RAGFlow 但简化**
   —— RAGFlow 的 DeepDoc 适合专业文档，MVP 用 markitdown + 按标题切块（800~1200 字）实现"够用"的检索，避免为追求论文级解析拖垮进度。

## 4. 财务引擎：公式清单（技术经济学核心，将配中文注释）

设计算期 n 年、基准折现率 i（可取行业基准或贷款利率上浮）：

- 各年净现金流 `NCF_t = 营业收入 − 经营成本 − 税金 + 折旧×税率效应 − 投资支出 ± 流动资金变动`（MVP 用简化口径，注释里写明假设）
- **NPV（净现值）**：`NPV = Σ_{t=0}^{n} NCF_t / (1+i)^t`（t=0 为初始投资，取负）
- **IRR（内部收益率）**：使 NPV=0 的折现率，用数值迭代（二分/牛顿）求解
- **动态投资回收期**：累计折现现金流转正的年数（线性插值到月）
- **盈亏平衡点（产量/收入）**：`BEP = 年固定成本 / (单价 − 单位变动成本)`
- **敏感性分析**：单因素 ±10% / ±20% → NPV 变动 → tornado 图
- **情景分析**：乐观/基准/悲观三套假设 → 三组 NPV/IRR → 期望与最差情形提示

> 每个指标在 `engine/` 内对应一个纯函数，公式出处（教材章节）写进 docstring —— 面试被问"IRR 怎么算的"时可现场讲代码。

## 6. 复用与合规边界（重要，面试可能被问）

- 直接作为依赖引入的第三方库：markitdown(MIT)、streamlit(Apache-2.0)、plotly(MIT)、python-docx(MIT)—— 全部宽松许可；
- 自研且零外部依赖：向量检索（numpy 余弦，约 100 行）；
- 只借鉴思路、未复制代码：RAGFlow 的 RAG 流程、LangGraph/OpenAI Agents 的多角色编排、NextChat/LobeChat 的交互；
- 自研并可在简历写"独立开发"：财务引擎、编排流水线、假设审核机制、模板体系、产品与业务文档；
- 项目自身开源许可建议 MIT，README 中注明借鉴来源（合规 + 加分）。
