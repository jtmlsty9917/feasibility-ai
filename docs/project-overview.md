# 项目从头到尾梳理（FeasAI · 面试前必读）

> 用途：面试/复盘前的"项目说明书"。看完你能把项目从 0 到 1 讲完整。
> 配套：resume-bullets.md（简历）、interview-qa.md（问答）、demo-script.md（演示）、smoke-report.md（真实验证证据）。

## 1. 一句话定位
FeasAI：面向**非财务决策者**（学生创业者 / 中小项目主 / 投资入门者）的可研工具——
输入项目参数或资料，输出**财务真算、带引用来源**的完整《可行性研究报告》，且可现场改参重算。

## 2. 为什么做（动机三层）
1. 专业执念：技术经济及管理的核心方法（NPV/IRR/敏感性/盈亏平衡）现实中大多数人不会用，想证明"专业知识能变成产品"；
2. 能力证明：一个项目同时覆盖 产品设计 + 财务建模 + AI 应用，适配 产品/AI产品/运营综合 三类求职方向；
3. AI 时代方法论：验证"人定义问题 + AI 辅助交付 + 测试验收"能端到端做出可用产品（应对"代码是不是 AI 写的"）。

## 3. 做了什么（时间线，真实发生过）
- M0（2026.09）：调研 GitHub 高星开源项目→确定"组装+自研"路线→PRD/架构/里程碑文档→项目骨架
- M1：自研财务引擎（现金流/NPV/IRR/回收期/盈亏平衡/敏感性/三情景），手算例题单测锁定
- M2：接入大模型与 RAG → 假设审核 + 报告流水线 + 资料问答；真实 DeepSeek 冒烟通过（好/坏项目两场景）
- M3：Word 导出、演示脚本、面试 QA、简历素材、离线预览、真实冒烟记录存档
- M3+：界面打磨（中文悬浮/宋体/宽松图表）、项目档案记忆系统、客观质检卡
- M4（进行中）：git 已推送 GitHub、录屏演示、简历定稿、模拟面试

## 4. 系统怎么运转（五步流水线，画得出来）
填写/导入参数 → ①AI 假设审核（人机协作）→ ②引擎真算（代码）→ ③RAG 查资料 → ④拼报告（财务代码生成、市场/风险 AI 执笔）→ ⑤交付 Word/质检卡。

## 5. 关键设计决策（每个都能讲"为什么"）
| 决策 | 为什么 | 面试价值 |
|---|---|---|
| 财务引擎纯 Python、零依赖 | 可手算验证、可测试、不信任黑盒 | "数字可信"的根基 |
| 大模型与财务计算硬隔离 | 杜绝 AI 编数字 | 回答"怎么防幻觉" |
| 提示词=角色+铁律+JSON 契约 | 结构化输出、可解析、可兜底 | 体现工程化，非"会聊天" |
| RAG 自研 numpy 检索 | demo 规模够用、能讲原理、接口可平滑换 FAISS | 展示原理理解 |
| 假设审核放"生成前" | 教育价值 + 可信度（人机协作） | 产品思考 |
| 质检卡"疑似=提示级而非否决" | 区分编数与合理建议，不误杀 | 测评设计的严谨 |
| Streamlit 一体式 | MVP 速度优先；演进路径清楚（React+FastAPI+DB） | 会选型、知边界 |

## 6. 验证与证据（能拿出手的数字，全部真实）
- 单元测试 41 项全绿（含手算例题、模型抽风数字安全、坏项目边界、档案存取、质检卡）
- 真实冒烟（DeepSeek）：单份完整报告 ≈24 秒 / ≈2,400 tokens / 成本几分钱
- 悲观压力场景：亏损项目正确判"不建议实施"，IRR 无解时优雅降级
- RAG 实测：上传样例→5 文本块；问"食品安全监管重点"命中目标章节相似度 0.60
- 记忆系统：项目档案 JSON 持久化，重启不丢（data/projects/，已 gitignore）
- 质检卡：章节完整/关键数字齐全/引用完整/成本自动检查
- GitHub 公开仓库：github.com/jtmlsty9917/feasibility-ai

## 7. 诚实边界（主动交代=专业）
- MVP/作品级：无多用户、登录、数据库；知识库向量在内存，重启需重传
- 市场/政策内容依赖用户上传资料与模型知识，不构成投资建议
- "AI 辅助开发"如实表述：作者负责产品、口径、验收；代码注释与测试保证可核查
